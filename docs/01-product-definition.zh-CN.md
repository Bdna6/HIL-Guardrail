# HIL — 产品定义

> 状态：M0 架构产出 · 需求来源：`PROMPT_HIL.md`（英文版为权威版本）

## 1. 一句话定位

**HIL（Human in the Loop）** 是一个轻量的、AI 原生的**人类决策权护栏**：让编码智能体（Claude Code、Codex 等）保持完全的能力与自主性，同时让人类在有分量的决策中保持实质性参与。

## 2. 问题

高能力智能体已经可以在一次长自主运行中选择架构、挑选依赖、定义 API、做出产品决策。失败模式不是产出质量差，而是**决策权的无声转移**：

```
用户："做一个这个功能。"
  → AI 选架构 → 选库 → 定义 API
  → 改数据模型 → 做产品决策 → 实现一切
用户："看起来不错。"
```

用户并非被违背意愿，只是不再被询问。HIL 的存在就是为了察觉这种漂移，并把注意力和决策权温和地交还给人。

## 3. 核心问题

不是*"AI 做了多少工作？"*，而是：

> **谁在做决策？**

## 4. HIL 是什么

- 一个本地运行的开源护栏，通过官方支持的集成点观察智能体会话。
- 一套**信任边界（Trust Boundary）**系统：用户声明自己已审查过哪些工具/库/服务；当智能体*实际引入*边界外的东西时，HIL 提醒——只提供意识，绝不限制。
- 一个温和的干预系统：简洁、中性、贴合上下文的提示（informational → attention → high importance），邀请人类判断。
- 默认静默。**静默是特性，不是缺陷。**

## 5. HIL 不是什么

| HIL 不是 | 原因 |
|---|---|
| 员工监控系统 | 没有使用时长、参与度百分比、排名 |
| 生产力仪表盘 | 设计上就没有指标界面 |
| "AI 使用量追踪器" | 信号不是使用量，而是决策归属 |
| AI 内容/剽窃检测器 | 与目标无关 |
| 强迫人肉干活的工具 | HIL 邀请的是**判断，不是劳动** |
| 削弱 AI 能力的手段 | 智能体始终全能力运行；HIL 绝不注入"多问问人"之类的粗劣提示 |
| 允许工具清单的执行器 | 信任边界从不限制智能体可以选择或推荐什么 |
| 打扰机器 | 冷却期、严重度阈值、会话/项目级静音、`/hil mute` 正是为防止骚扰而存在 |

## 6. 目标用户

- 每天与 Claude Code / Codex 协作的独立开发者。
- 希望把共享、可审查的信任边界作为项目配置的团队（不是对人的监督）。
- 任何希望在智能体自主性增强的同时依然自己做主的人。

## 7. 产品承诺

1. **不降低能力。** HIL 绝不削弱智能体，绝不添加"多让人类参与"这类粗劣提示。
2. **提供意识，不下裁决。** HIL 陈述事实（"X 在你的信任边界之外"）与审查要点（数据流、凭据、许可、锁定），没有可验证证据绝不宣称工具"不安全"。
3. **本地与隐私。** 本地处理、本地配置、临时会话状态、无遥测。
4. **有分寸的打断。** 每次干预都解释触发原因、可关闭，并把决策——而不是工作——交还给人。
5. **第一天起双语。** 文档、提示词、所有用户可见字符串均为英文+简体中文；架构为更多语言预留扩展。

## 8. 产品身份

不是*"限制 AI 的工具"*。

> **在高度自主的 AI 工作流中保护人类决策权的工具。**

> AI 可以执行。AI 可以推理。AI 可以创造。
> 人类应当对有分量的决策保持知情并实质参与。

理想的干预感受是：

> *"我可以继续。但这正在变成你的决策，而不只是我的任务。"*

## 9. 成功标准

- 日常自主工作（测试、重构、调试）中，HIL 隐形：零干预。
- 当智能体越过用户的信任边界（如安装未审查的云 SDK），用户看到一条简洁中性的警示，并以 Allow / Reject / Investigate 做出决定。
- 长时间漂移场景（连续多个重大决策 + 反复低信息量的"看起来不错"）中，HIL 只发出一条升级提示——不是一连串。
- 用户对 HIL 的描述是*"它提醒我什么时候在交出本该自己做的决策"*，而不是*"它教我怎么干活"*。
- 没有人因为烦躁而卸载。

## 10. 范围之外（v1）

- 任何形式的人类生产力度量或报告。
- 按策略强制执行/封禁工具（信任边界负责提醒，不负责禁止）。
- 集中式或托管部署；HIL 是本地工具。
- 在适配器层之外硬编码任何智能体。
