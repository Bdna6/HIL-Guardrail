## 2. 风险

### 2.1 技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 误报让用户烦到卸载 | 对采纳是致命的 | v1 高级别干预只用确定性信号；不确定即降级 informational；每个信号 PR 过场景语料门禁（文档 07） |
| hook 延迟拖慢智能体体验 | 高 | < 50 ms p95 预算、热路径仅本地、fail-open；性能测试进 CI |
| 上游接口变动（Claude Code / Codex hook schema） | 中 | 适配器契约测试钉住精确 JSON；只有适配器接触原生格式 |
| Codex 缺 `ask`（deny 比 HIL 哲学更强硬） | 中 | 如实文档化；理由措辞交还决策给用户；冷却防 deny 循环；可用时优先 `PermissionRequest` 落空（文档 05 §4） |
| 命令解析漏掉安装变体（漏报） | 低–中 | 仅观察的代价低；语料随真实使用增长；漏报以场景缺口显形，不伤用户 |
| Windows shell 多样性（cmd/PowerShell/git-bash 形态） | 中 | 单元语料从第一天起覆盖三种形态（开发机即 Windows） |
| SQLite/Node 版本耦合（`node:sqlite` 可用性） | 低 | Node ≥ 20 门槛；M2 时按需决定备用驱动 |

### 2.2 产品风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 功能需求漂向监控（"加个参与度指标嘛"） | 生存级（产品身份） | schema 无身份/聚合维度；每个 PR 对照设计之问（文档 02 §7）；评审中引用规范 §24 拒绝 |
| 信任边界编写摩擦（"默认为空 → 什么都提醒"） | 高 | 空边界 ⇒ v1 行为是每类目提醒一次+冷却，而非连环骚扰；起步模板；从警示里直接 `hil trust add` |
| 用户把 HIL 感知为"限制 AI" | 高 | README 以产品身份开篇（文档 01 §8）；面向智能体的文本绝不削弱能力；Claude Code 上绝不使用 deny |
| 双语维护漂移 | 中 | en 为权威；CI 强制 locale 键对齐；zh-CN 漂移按 bug 处理 |
| 范围蔓延（智能体特有功能漏进 core） | 中 | core 不 import 任何适配器内容（体系结构文档 §1）；评审规则 |
