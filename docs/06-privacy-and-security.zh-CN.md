# HIL — 隐私与安全架构

> 状态：M0 架构产出 · 覆盖：隐私架构（规范 §24）、安全与依赖/许可意识（规范 §9、§14）。
> 隐私是一等架构要求，不是功能点。

## 1. 隐私原则 → 具体设计

| 原则 | HIL 中的具体规则 |
|---|---|
| 本地处理 | 所有确定性分析都在本地进程运行。hook 路径无网络。 |
| 本地配置 | 信任边界存于 `~/.hil/` 与项目内 `.hil/`。不同步到任何地方。 |
| 临时会话状态 | 每会话一个 JSON，`SessionEnd` 删除，按年龄清理兜底。绝不跨会话聚合。 |
| 最小留存 | SQLite 只存**用户自己编写**的信任配置与偏好。schema 里根本不存在活动记录表。 |
| 用户透明 | `hil status` 与 `hil review` 展示 HIL 关于当前会话所知的一切。`docs/` 记录 HIL 写入的每个文件。 |
| 显式配置 | 改变行为的选项一律 opt-in（语言、语义层、未来集成）。 |
| 无隐藏遥测 | v1 **零**遥测。若未来引入：显式 opt-in、文档化载荷、默认关闭——按规范 §24。 |
| 无监控面 | 不存在任何能回答"人干了多少活/参与度多少"的 API、表、导出或报告。要退化成那种产品需要重设计 schema——这是有意设置的阻力。 |

### 1.1 点名的反模式（规范 §24）

```
员工 A — AI 使用 4.8 小时 — 人类参与度 32%
员工 B — AI 使用 3.1 小时 — 人类参与度 71%
```

这不是 HIL。数据模型无法表达它：没有用户身份维度、没有聚合层、没有参与度指标。决策权六维度（见概念模型文档）只存在于单个会话的临时推理状态里。

### 1.2 语义层数据流（M4+）

可选 LLM 层运行时只发送：任务语境摘要、压缩后的决策日志（标题/层级/实体名）以及具体问题——**绝不**发送完整转录、文件内容或凭据。用户可以完全关闭该层（`semantic.enabled: false`），HIL 的确定性信号不受影响。

## 2. HIL 自身的安全姿态

- **权限**：HIL hook 进程以用户权限运行，与 Claude Code 相同。HIL 绝不提权，绝不写 `~/.hil/`、`.hil/` 及自身安装/卸载目标（`settings.json`、`.claude/commands/`）之外的位置——后两者只在显式 `hil install` 时触碰。
- **输入信任**：hook stdin JSON 防御性解析（schema 校验、大小上限）。畸形输入 → fail-open，仅本地记日志。
- **注入抵抗**：干预文本由 i18n 模板 + 实体名生成；实体名渲染进权限理由前先做净化，恶意包名无法把控制文本走私进提示（`permissionDecisionReason` 按契约是纯文本）。
- **状态文件**：平台支持时以仅用户可读写权限写入；状态目录设计上不含任何机密（HIL 从不读取凭据）。
- **fail-open**：HIL 出错绝不阻塞用户会话（见体系结构文档 §9）。用户工作流的安全绝不依赖于 HIL 健康。

## 3. 依赖与许可意识（风险筛查，不是裁决）

HIL 帮助人类**筛查与调查**风险（规范 §9），不做判断：

### 3.1 信任边界越界时呈报的事实性审查要点

数据流 · 网络访问 · 凭据及其控制者 · 外部权限 · 依赖来源 · 供应链暴露 · 外部服务 · 数据存储位置 · 许可证 · 维护状态 · 厂商锁定 · 攻击面 · 隐私影响。

以问题清单形式呈现，不是断言。没有可验证证据，HIL 绝不说"X 不安全"；默认表述恰恰是：**"X 在你配置的信任边界之外。"**

### 3.2 许可意识（规范 §14）

当引入的依赖有许可元数据时（来自包注册表清单或 lockfile，仅在热路径之外按需获取），HIL 事实性地报告许可类别：

```
MIT · Apache-2.0 · BSD · GPL · AGPL · Commercial · Unknown
```

使用中性措辞，例如：

> "该依赖使用 GPL-3.0。取决于最终软件的分发方式，这可能引入许可义务。建议继续之前审查该许可证。"

不把任何许可证标注为"安全"或"不安全"；义务取决于使用与分发方式，这属于人类。

### 3.3 可扩展

风险筛查清单与许可类别由 locale/数据驱动；新增领域（如依赖内遥测检查）无需触碰干预引擎。

## 4. HIL 自身的供应链

- 依赖预算最小化：热路径零第三方依赖（仅 Node 内建：`node:sqlite`、`fs`、`path` 等）。CLI 侧依赖保持为短且经审计的清单。
- 提交 lockfile；CI 跑 `npm audit`；CI 强制依赖无 post-install 脚本。
- HIL 本身采用 MIT 许可；版权署名 `BDNA6`（作者提供；规范 §13——绝不虚构）。
