# HIL — 概念模型

> 状态：M0 架构产出 · 覆盖：核心概念模型、人类决策权（Human Agency）、决策归属（Decision Ownership）、信任边界（Trust Boundary）、干预（Intervention）、范围扩张（Scope Expansion）。
> 设计规则：这些模型服务于**干预推理**，绝不汇总为人类的"评分"。

## 1. 核心概念模型

HIL 通过三个原语理解智能体会话中的每个观察到的瞬间：

```
Event（事件）     发生了什么（归一化的工具调用、消息、命令、文件变更）
Decision（决策）  一个有后果的选择（选哪个技术、哪条路线、哪种行为）
Owner（归属者）   谁做的——人类（明确给出或授权委托），还是智能体（自行假定）
```

当一个**事件**隐含一个**决策**，其**归属者**是智能体而后果层级（见下）又高时，这个事件才变得有趣。这一句话就是整个分析引擎；其余一切都是对它的细化。

## 2. Human Agency 模型

六个维度，按会话定性评估——绝不求和、绝不换算百分比：

| 维度 | 问题 |
|---|---|
| 发起（Initiation） | 人类是否定义了问题、目标、约束、成功标准？ |
| 导向（Direction） | 人类是否选择方向、设定优先级、消解歧义、调整目标？ |
| 判断（Judgment） | 人类是否在备选间做出选择、接受/否决提案、做权衡、质疑推理？ |
| 创造（Creativity） | 人类是否贡献了原创想法，或对 AI 生成的想法做了转化/组合？ |
| 验证（Verification） | 人类是否对重要结果做了有意义的审查？ |
| 承担（Ownership） | 人类是否理解已完成的内容并自觉接受最终决策？ |

关键立场（规范 §37）：决策权 ≠ 活动量。`人类执行 10% / AI 90%` 可以非常健康；`50/50` 也可能毫无决策权。人类一句小的介入（"用 Postgres，别用 Mongo，那个会丢数据"）所承载的决策意义，可能超过人类亲手敲的几百行。

## 3. Decision Ownership 模型

后果分级（规范 §5），每级对应默认干预姿态：

| 层级 | 示例 | 默认姿态 |
|---|---|---|
| 1 · 执行 | 跑测试、格式化、重命名、修语法、常规重构 | 只观察，绝不干预 |
| 2 · 推理 | 根因分析、诊断失败、权衡说明 | 仅在连续成串时产生轻度意识信号 |
| 3 · 重大 | 架构、数据库/后端/前端框架、认证、数据模型、API 契约、重大依赖、不可逆选择 | 主干预区 |
| 4 · 创造/战略 | 产品行为、UX 方向、功能范围、算法发明、交互哲学 | 敏感度最高；默认归属人类 |

引擎把智能体活动分类为 `execution | reasoning | decision | creativity`——绝不把所有模型活动等同视之。

## 4. Trust Boundary 模型

### 4.1 实体

智能体可能引入或依赖的任何东西，按可扩展的类别组织：

- **libraries（库）** — React、FastAPI、PyTorch、Prisma
- **databases（数据库）** — PostgreSQL、MongoDB、Redis、Supabase、Firebase
- **external services（外部服务）** — AWS、Stripe、Auth0、S3、OpenAI、第三方 API
- **plugins / MCP / 智能体工具** — MCP 服务器、浏览器自动化、文件系统工具、远程执行
- **CLI / 基础设施** — Docker、kubectl、Terraform、云 CLI
- **data sources（数据源）** — 外部 API、远程数据库、第三方数据集、抓取服务

新类别是数据而非代码——增加类别不允许要求改动核心。

### 4.2 信任状态

```
unknown     未审查；默认状态
reviewed    用户已考察；无异议
trusted     用户明确放心；绝不打断
restricted  使用前总是询问（不是封禁——是"必须显式确认"）
temporary   在有限范围/时间内受信（会话级或带过期）
```

### 4.3 作用域

```
global   （~/.hil/config + 用户库）   例：Python、GitHub
project  （仓库内 .hil/config）       例：React、PostgreSQL、AWS
session  （临时会话状态）             例："行，就今晚用 Stripe"
```

查找优先级：session → project → global → `unknown`。组合必须可解释：`/hil trust` 能展示每个判定到底来自哪个作用域。

### 4.4 不变式

信任边界**不是允许工具清单**。HIL 绝不告诉智能体"只能用受信工具"或"不要推荐边界外的库"。智能体保有推理与提议的完全自由。HIL 只在智能体**实际引入、安装、连接、配置或依赖**边界外实体的那一刻行动——即便那时，动作也只是*呈报给人类*，而不是按策略拦截。

## 5. Intervention 模型

### 5.1 触发证据（规范 §18）——多信号合并，绝不依赖朴素阈值

正在发生重大决策 **且/或** 人类参与异常低 **且/或** 智能体决策权持续累积 **且/或** 范围实质扩张 **且/或** 引入未审查工具 **且/或** 数据/安全/隐私/许可/基础设施边界变化 **且/或** 创造/战略权向智能体漂移。

明确拒绝作为主要机制：`N 次工具调用`、`N 分钟`、`N 行代码`。这些是弱代理指标；上下文与后果才是主导。

### 5.2 级别

| 级别 | 适用 | 语气示例 |
|---|---|---|
| Informational | 低置信度、第 2 层信号 | "我对方向做了几个假设。继续之前值得快速看一眼。" |
| Attention | 连续多个第 3 层决策无人类输入 | "我已经在没有你多少输入的情况下做了几个重大实现决策。要审查一下方案吗？" |
| High importance | 越过信任边界；第 4 层漂移；不可逆动作 | "接下来涉及之前未审查过的架构与外部依赖。我可以自主继续，但这是一个有分量的决策点。" |

### 5.3 风格规则

简洁 · 贴合上下文 · 中性 · 解释为何触发 · 无评判性语言 · 交还决策权。绝不邀请体力劳动。文案本地化（en/zh-CN）且可配置，绝不硬编码。

### 5.4 防骚扰机制（规范 §21）

分级置信阈值 · 严重度门槛 · 分类目冷却期 · 三种粒度的用户覆盖（单次/会话/项目）· 临时信任授予 · 自适应阈值（用户总是秒批的类别停止升级）。

## 6. Scope Expansion 模型

智能体未经授权实质超出用户的任务（规范 §17）：

```
用户："修一下登录 bug。"
智能体：重写认证 → 改数据库 schema → 换认证框架
       → 引入第三方身份提供商
```

检测是语义性的（对比任务意图与决策轨迹），辅以确定性锚点：超出隐含范围的编辑、新配置/服务、schema 迁移、超出修复需要的新依赖。单个锚点很弱；模型在*模式*上触发——原始请求 + 偏离幅度 + 偏离部分的后果层级。

## 7. 设计之问（持续自检）

> HIL 是在保护人类决策权，还是只是在度量人类活动？

每个功能都对照此问：如果一个机制只能被解释为"对人做度量"，它就不上线。
